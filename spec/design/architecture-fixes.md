# 架构审阅修复

2026-11-11. 按阶段实现并独立提交; 本批不实现持久化.

## F1. 输入错误隔离

Worker 授权接收与其他接收路径一致: Delete、超限负载、错误路由和无效编码只拒绝当前消息; 连接故障与内部状态错误仍交给生命周期组处理. 新增真实 Zenoh 回归, 验证超限及坏 JSON 后仍可执行下一授权、收录原 Report 并正常排空.

六个阶段分别记录如下; 每阶段包含相应验收并独立提交.

## F2. 接收队列过载隔离

Zenoh 回调先尝试预留有界队列位置, 再校验和复制负载, 不阻塞共享接收线程. 满时丢弃新消息, 保留已入队消息, dropped_messages 提供订阅独立的饱和计数. 发送成功不意味着入队或接纳; 关键消息继续通过原身份回执/重投及查询补齐. 真实双订阅测试验证一个满队列不阻塞另一个订阅, 原队列消息不被覆盖且恢复后可重交原消息.

## F3. 首份 Report 额度

Authority 接纳新 Operation 时同时预留首份 Report 的位置. 附加报告只能使用未预留空间; 首份报告用掉自身预留, 合法重复报告不重复计费. 因此附加证据可能提前阻止新 Operation 接纳, 但不会挤占已接纳请求的首次完成证据. 无持久化、淘汰或新容量原语. 两个回归测试先在旧实现失败, 修复后验证附加报告、非法绑定、重复报告以及两种提交入口都遵守此约束.

## F4. 本地角色交付与独立推进

beamlet::local_delivery 负责本地待派发授权补送、任务启动与报告收录, LocalExecution 和 Node 复用同一流程. 暂满队列保留 Authority 的 Accepted 事实, 后续推进复用原授权; 绑定错误与永久记录容量不足仍明确返回错误. Node 不在提交分支等待工具完成, 而是将本地完成等待与消息、查询、停止信号并列驱动. 应用仍显式选择角色与基础设施. 真实网络回归先复现长任务阻塞查询, 再验证等待期间可查询、解除等待后可排空; 库测试验证队列满后两份原授权都完成且不会重复执行.

## F5. 嵌套执行活性

移除通用 Limits.max_concurrency, Worker 启动已接纳的排队 Attempt, 不把整个 Operation 生命周期当作资源占用. 保留队列与身份记录上限; 不新增全局容量或调度层. 具体资源的限流由应用传入的执行逻辑在实际使用期间显式持有, 父执行等待子工作时不持有子工作所需许可. 回归先复现八个等待父任务占满名额、子任务无法启动, 修复后十六份报告全部完成; 同一测试用独立资源信号量证明叶子工作仍可限制为并发一. 记录容量不足仍拒绝新的子请求, 调用方必须处理该拒绝, 不保证无限嵌套.

## F6. 演示协议归属

严格 v0 JSON、Hello、固定 echo/delay/fail、回执与生命周期编解码迁至独立 adapters/beamlet-protocol-demo. Node、Console 和传输测试显式依赖此 Adapter, 不再启用或导入 beamlet-agent::testing. Agent crate 仅保留未来实体和 Loop 的入口, 不提供兼容转导出. 新 crate 名称明确这些仍是演示契约, 不将固定 Hello/TestTask 冒充通用任务协议. 通用领域、驱动与编解码接口仍由 beamlet 提供; 未新增传输或持久化后端.
