# 实现顺序与验收

状态: 2026-11-10 的实现准备, 本批仅记录设计与实现顺序. 按 [设计入口](README.md)及关联契约实施, 不将接口草案或候选命名当作已发布 API.

具体执行按 [实现任务与提交](implementation-tasks.md)逐项推进. 每个任务完成实现, 验证及相关文档更新后单独 commit, 保持每个提交可构建且可独立审阅.

## 分阶段交付

### 1. 整理通用执行入口与观察 Interface

将通用 Authority/Worker 能力与新 Agent 实体解耦. 为当前本地组合入口选择不混淆领域 Agent 的名称并直接迁移调用方. 实现 [Client 契约](execution-client.md)的最小提交, 原键查询, Operation/Report 查询和结果观察, 先用现有假执行器.

Node/Console 作为公开库接口的调用者. 将相关的提交关联, 去重/重投, 查询与观察合并, 角色驱动及生命周期协调下沉到对应库; 应用保留参数/交互处理, 显式组装, 信号转换和展示. 独立提供角色构造, 依赖绑定和启动/停止接口, 基础设施由应用选择并传入; Node 组装辅助可选. 同时调整已有调用点, 使新增接口承担实际流程, 不只在原应用实现外加一层转发.

验收: 同进程与跨进程返回相同事实; Report 早于接纳回执; 订阅前完成; 查询/通知重复倒序; 通知丢失后查询补齐; 错绑定和权限拒绝; 不为每次调用重建连接.

分层验收: 不启动 Node/Console CLI 的库调用者可完成相同执行与观察流程; 可复用库不依赖应用 crate; Node/Console 不另写一套去重, 重投或状态推进规则. 核心契约测试调用公开库接口, CLI 测试覆盖参数, 装配和输出.

组装验收: 独立 Client/Authority/Worker 可由调用方显式绑定并驱动; 本地内存组合无需建立 Zenoh 或 SQLite 连接; 消息/存储 Adapter 可在组装处按已支持模式选择; 创建角色不隐式启动其他角色或基础设施; 关闭单个角色不破坏仍被其他角色使用的共享资源. 不以增加统一容器或通用插件框架替代这些公开接口.

### 2. 落地 Diesel + SQLite 与故障窗口

先实现 Authority/Worker 的持久记录, 接纳/交付事务, 版本迁移和异步数据库调用. 对 [恢复表](persistence-recovery.md)逐窗口注入故障. 单独完成稳定身份与新实例恢复绑定, 验证后才开放自动续行范围.

验收: 提交成功才确认; 提交结果未知时查询原标识; 相同 key/Attempt/Report 跨重启去重; 不同内容冲突; 原授权与原 Report 重交; 可能执行但无结果时不重跑; 原预算不因重启刷新; 数据库不可用不降级成新执行.

### 3. 实现 Agent 实体与固定输出的 Loop

实现最小 Agent 存储, preset/override, 创建关联与幂等初始化, Processing/Waiting/Suspended 推进, 消费与派生动作的一致写入. 保存已发布回答并提供查询与通知. 用固定 LLM 输出和假工具跑通完整 Loop, 在这一阶段落地并验证 Agent 的持久化, 不把假模型通过误称为真实 LLM 集成.

验收: 同配置的独立创建请求产生独立 Agent; 原提交/Attempt 重传不重复创建或启动执行, 恢复沿用原关联; 新输入交给原 Loop; 重复 Report 仅派生一次; 同参数不同调用保持独立; 异步工具不阻止无依赖工作, 结果进入后续 LLM, 工具完成至后续提交之间也不提前结束; 全部子执行和结果处理完成后正常结束; Loop 最终结果已保存而未交付时不重跑; preset 更新不改变原请求.

UI 验收: Loop 尚未结束时可收到已保存回答; 保存后通知丢失可查询补齐; 重复 Report/通知不重复发布或显示; Loop 结束后仍可查询已有回答.

### 4. 接入工具与 Codemode, 验证输入投影和 fork

按固定 capability 契约接入具体执行器与受限 Codemode 工具 Interface. 本地小计算不递归变为 Operation, 显式调用保留完整关联. 先确认假工具路径和权限, 再接真实 LLM/文件工具. 不把沙箱引擎选择当成已确定结论.

验收: 一个 Codemode 调用多个工具并返回自身 Report; 部分子工具失败与未知结果不被隐藏; 相同代码重传不重新执行; Codemode 崩溃不从头自动重放; provider 调用/结果配对与完整请求保存; fork 复制数据但不复制执行权, 副本可独立加载, 删除来源不破坏引用; 有未处理责任时拒绝 fork.

### 5. 补齐部署配置与测量

让身份, 角色与基础设施接入独立配置, 支持同进程组合和必要的分节点部署. 第一版官方存储仍为本地 SQLite; 远程存储仅在出现实际部署需求时实现. 保持生命周期/Draining 与业务完成语义分开.

验收: 身份冲突/非法配置在执行前报告; 无数据库模式明确为易失; 子调用不因自定义资源限制陷入相互等待; 停止服务启动工具不误杀外部托管服务. 测量空工具往返的本地/跨进程/持久化开销及多个独立请求并发, 不预设性能数值.

## 测试与证明范围

优先测试契约可观察的行为: 去重, 绑定, 消费一次, 故障恢复, 引用保留和输入重建. 需要故障注入的数据库事务与进程窗口不能只用成功路径单元测试替代. 本地受控假工具通过不等于任意真实工具具有相同恢复能力.

后续各阶段继续遵守库优先原则: 持久化, Agent Loop, UI 输出观察, Codemode 和 fork 的可复用行为在库中实现, Node/Console 通过同一公开接口接入. 抽取已有行为时迁移相应契约测试, 应用保留必要的集成验证, 不复制相同状态机测试作为分层证明.

既有协议文档中的"不新增测试"属于当时原型批次, 不作为未来持久化/Agent 功能的测试限制. 新代码批次按实际风险增加必要验收, 运行相关现有测试和仓库检查; 本文不要求文档变更运行 Rust 测试.

## 当前明确暂缓

Sub-Agent, Agent 间调用协议, MCP Sampling, 任意代码检查点/确定性重放, 运行中 fork, 动态能力注册, 自动跨节点接管, 全局共识和外部影响 exactly-once. 不新增 Task 层, 公开 AgentRuntime 实体, 独立 Tool Reply 权威账本, 全局并发名额或强制双执行池.

WIT/Protobuf 仅参考 Interface 表达格式. 不引入新传输协议栈或数据库后端作为上述阶段的前置条件. 创建身份与执行去重, 持久化提交顺序, 子调用关联和恢复不确定性优先于抽象扩张.
