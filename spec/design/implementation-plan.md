# 实现顺序与验收

状态: 2026-11-10 的实现准备, 本批仅记录设计与实现顺序. 按 [设计入口](README.md)及关联契约实施, 不将接口草案或候选命名当作已发布 API.

## 当前代码与目标差距

| 范围 | 已有实现 | 仍需实现 |
| --- | --- | --- |
| Kernel | Operation/Attempt/Report, Effect, Authority 观察与 Worker 阶段规则 | 目标契约要求的演进; 不是新增 Task 或全局状态机 |
| 执行路径 | 有界内存账本, 本地类型化交付, Zenoh 固定任务演示 | 通用 capability 接入与组合调用 Interface |
| 回执 | Operation/Attempt/Report 三段回执与有限原消息重投 | 持久提交后确认, 重启恢复与旧实例隔离 |
| Node | 角色组合, 稳定/运行身份配置, 生命周期, 心跳, Draining | 稳定身份解析, 基础设施独立接入与明确运行模式 |
| Agent | `beamlet-agent::Agent` 目前只是本地 Authority/Worker 包装 | 新 Agent 实体, preset/override, Loop, fork, 上下文投影 |
| 存储与工具 | Diesel SQLite 依赖, durable/tool crate 脚手架 | Agent/执行存储, 事务与迁移, LLM/工具/Codemode 执行器 |

本批仅编写和核对文档. 不把以往会话中的测试次数当作本次运行结果, 不宣称持久性或安全协议已实现.

## 实现前的必决项

| 问题 | 已确定的约束 | 尚需决定的实现细节 |
| --- | --- | --- |
| Agent 单写者 | 同时一个活动 Loop, 预留早于提交, 旧执行者不得继续推进 | 活动归属的条件写入/代次及外部调用路径检查 |
| 实例更替 | 保留历史实例绑定, 不靠失联自动接管 | 授权续行, 旧实例隔离, 旧证据的新传输信封与回执绑定 |
| 完成与停止 | 正常完成须收齐异步工具; 停止不等于取消或无影响 | stop 的请求/响应, 异常终止和未确认责任的处置交接编码 |
| 配置与版本 | preset/capability 固定版本, 实际 LLM 请求可追溯 | preset 引用格式, override 合并规则, schema 版本与迁移 |
| Report 影响字段 | 无影响/已观察/未知与执行结果独立 | `Effect` 的最终替代名称及效果范围说明 |

恢复执行权的机制未明确前, 只允许实现可验证的恢复查询与记录保留, 不自动续行不确定执行. 不为解决这些问题提前增加共识系统或通用 Workflow 框架.

## 分阶段交付

### 1. 整理通用执行入口与观察 Interface

将通用 Authority/Worker 能力与新 Agent 实体解耦. 为当前本地组合入口选择不混淆领域 Agent 的名称并处理兼容入口. 实现 [Client 契约](execution-client.md)的最小提交, 原键查询, Operation/Report 查询和结果观察, 先用现有假执行器.

验收: 同进程与跨进程返回相同事实; Report 早于接纳回执; 订阅前完成; 查询/通知重复倒序; 通知丢失后查询补齐; 错绑定和权限拒绝; 不为每次调用重建连接.

### 2. 落地 Diesel + SQLite 与故障窗口

先实现 Authority/Worker 的持久记录, 接纳/交付事务, 版本迁移和异步数据库调用. 对 [恢复表](persistence-recovery.md)逐窗口注入故障. 单独完成稳定身份与新实例恢复绑定, 验证后才开放自动续行范围.

验收: 提交成功才确认; 提交结果未知时查询原标识; 相同 key/Attempt/Report 跨重启去重; 不同内容冲突; 原授权与原 Report 重交; 可能执行但无结果时不重跑; 原预算不因重启刷新; 数据库不可用不降级成新执行.

### 3. 实现 Agent 实体与固定输出的 Loop

实现最小 Agent 存储, preset/override, 活动 Loop 预留, 单写者, Processing/Waiting/Suspended 推进, 消费与派生动作的一致写入. 用固定 LLM 输出和假工具跑通完整 Loop, 在这一阶段落地并验证 Agent 的持久化, 不把假模型通过误称为真实 LLM 集成.

验收: 两个启动请求或两个 Authority 不能同时推进同一 Agent; 新输入不隐式开启第二 Loop; 重复 Report 仅派生一次; 同参数不同调用保持独立; 异步工具不阻止无依赖工作但阻止正常完成; Loop 最终结果已保存而未交付时不重跑; preset 更新不改变原请求.

### 4. 接入工具与 Codemode, 验证输入投影和 fork

按固定 capability 契约接入具体执行器与受限 Codemode 工具 Interface. 本地小计算不递归变为 Operation, 显式调用保留完整关联. 先确认假工具路径和权限, 再接真实 LLM/文件工具. 不把沙箱引擎选择当成已确定结论.

验收: 一个 Codemode 调用多个工具并返回自身 Report; 部分子工具失败与未知结果不被隐藏; 相同代码重传不重新执行; Codemode 崩溃不从头自动重放; provider 调用/结果配对与完整请求保存; fork 复制数据但不复制执行权, 副本可独立加载, 删除来源不破坏引用; 有未处理责任时拒绝 fork.

### 5. 补齐部署配置与测量

让身份, 角色与基础设施接入独立配置, 支持同进程组合和必要的分节点部署. 第一版官方存储仍为本地 SQLite; 远程存储仅在出现实际部署需求时实现. 保持生命周期/Draining 与业务完成语义分开.

验收: 身份冲突/非法配置在执行前报告; 无数据库模式明确为易失; 子调用不因自定义资源限制陷入相互等待; 停止服务启动工具不误杀外部托管服务. 测量空工具往返的本地/跨进程/持久化开销及多个独立请求并发, 不预设性能数值.

## 测试与证明范围

优先测试契约可观察的行为: 去重, 绑定, 消费一次, 故障恢复, 引用保留和输入重建. 需要故障注入的数据库事务与进程窗口不能只用成功路径单元测试替代. 本地受控假工具通过不等于任意真实工具具有相同恢复能力.

既有协议文档中的"不新增测试"属于当时原型批次, 不作为未来持久化/Agent 功能的测试限制. 新代码批次按实际风险增加必要验收, 运行相关现有测试和仓库检查; 本文不要求文档变更运行 Rust 测试.

## 当前明确暂缓

Sub-Agent, Agent 间调用协议, MCP Sampling, 任意代码检查点/确定性重放, 运行中 fork, 动态能力注册, 自动跨节点接管, 全局共识和外部影响 exactly-once. 不新增 Task 层, 公开 AgentRuntime 实体, 独立 Tool Reply 权威账本, 全局并发名额或强制双执行池.

WIT/Protobuf 仅参考 Interface 表达格式. 不引入新传输协议栈或数据库后端作为上述阶段的前置条件. Agent 单写者, 持久化提交顺序, 子调用关联和恢复不确定性优先于抽象扩张.
