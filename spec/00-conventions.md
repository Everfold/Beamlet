# 规范基础约定

## 规范性关键词

按 RFC 2119 区分强制等级：

- **必须（MUST）** / **不得（MUST NOT）**：硬性契约约束，违背即不合规。
- **应当（SHOULD）** / **不应当（SHOULD NOT）**：默认要求，仅在明确记录原因时允许偏离。
- **可以（MAY）**：允许的实现自由度。

## 跨模块通用规则

1. **原语身份与业务数据中立**：核心原语的身份与业务请求/结果类型由上层或调用方决定；内核与台账不得解析业务请求与结果的内容，也不得按内容相等替代身份相等。
2. **字符串标识精确比较**：当上层以字符串表示 `operation_id`、`attempt_id`、`report_id`、`Pool` 或 `CapabilityId` 时，必须按原始字符或字节精确匹配，不得修剪空白、折叠大小写或解析语义。
3. **本地单调时钟**：所有租约存活判定、等待超时与排空截止时间，必须基于观测方自身本地单调时钟计算，不得依赖发件方时间戳或跨进程时钟同步。
4. **正数有限期限与容量**：有限超时期限、心跳周期与缓冲容量在构造阶段必须拒绝零值及超出时钟或运行时表示范围的值。
5. **逻辑 IDL 定位**：Protobuf Edition 2026（[messages.proto](proto/beamlet/v1/messages.proto)）仅定义与传输后端无关的跨角色逻辑消息结构，任意业务载荷以 `bytes` 表示，不规定线编码格式或具体消息传输中间件。
6. **术语书写准则**：规范正文使用中文，领域原语、状态名与公开契约名保留英文原词；术语词义以 [00-glossary.md](00-glossary.md) 为准。
